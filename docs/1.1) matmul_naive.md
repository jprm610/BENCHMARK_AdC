# `matmul_naive` — el algoritmo

## Qué computa

$C = A \cdot B$, donde $A$ es $m \times l$, $B$ es $l \times n$, $C$ es $m \times n$.

Cada elemento $C_{ij}$ es el producto punto de la fila $i$ de $A$ por la columna $j$ de $B$:

$$C_{ij} = \sum_{k=0}^{l-1} A_{ik} \cdot B_{kj}$$

## El código

```c
for (size_t i = 0; i < m; ++i) {
    for (size_t j = 0; j < n; ++j) {
        scalar_t acc = 0;
        for (size_t k = 0; k < l; ++k) {
            acc += A[i * l + k] * B[k * n + j];
        }
        C[i * n + j] = acc;
    }
}
```

## Patrón de acceso a memoria

Con `k` variando en el bucle interno y `j` fijo:

| Acceso | Stride | Localidad |
|--------|--------|-----------|
| `A[i*l + k]` | 1 elemento | Buena — secuencial |
| `B[k*n + j]` | `n = 128` elementos (512 bytes) | Mala — salta de fila en fila |

## Por qué es lento

La caché trae líneas de 64 bytes (16 floats) por transferencia. Cada acceso a `B[k*n + j]` trae los elementos $B_{k,j}$ hasta $B_{k,j+15}$, pero el siguiente acceso es $B_{k+1,j}$ — 512 bytes más adelante, en otra línea completamente diferente. Los 15 floats que vinieron de regalo nunca se usan antes de que la línea sea expulsada.

**87.5% de cada transferencia de memoria se desperdicia.**

Para `m = 1024`, `B` ocupa `1024 * 128 * 4 = 512 KB` — ya no cabe en L2 (512 KB por core en el Ryzen 5 4600H). Cada acceso al bucle interno es prácticamente un cache miss garantizado.
