# Makefile — Referencia de uso

## Flujo principal

```
make build          # 1. Compilar todo (bench + validate + tests)
make tests          # 2. Unit tests (rápidos, prerequisito de validate)
make validate   # 3. Verificar corrección (puerta antes de medir)
make results        # 4. Sweep perf → results/metrics.csv
```

---

## Targets principales

### `make build` / `make all`

Compila los 8 binarios `bench_*_ZEN5`, los 8 `validate_*` y los 4 unit-tests sin ejecutar nada.
No acepta argumentos.

```bash
make build
```

---

### `make tests`

Compila y ejecuta los 4 unit-tests en orden (`test_matrix_utils`, `test_morton`, `test_kernel_avx512_morton`, `test_kernel_avx512_tiled`). Para en el primer fallo. Sin argumentos.

```bash
make tests
```

Detalle de cada test en [`1.9) tests.md`](<1.9) tests.md>).

---

### `make validate`

Depende de `make tests`: corre primero los unit-tests, y solo si pasan ejecuta los 8 `validate_*` en secuencia. Para en el primer fallo. Sin argumentos.

Los primeros 4 son escalares compilados en `-O0`; los últimos 4 usan
`-march=native` con AVX-512 y requieren hardware compatible.

```bash
make validate
```

---

### `make results`

Target principal. Construye todos los benchmarks, lanza el sweep de hardware
counters con `perf` y consolida la salida en `results/metrics.csv`.

```bash
make results                                          # defaults completos
make results MS="1024 4096"                           # solo esos tamaños
make results VARIANTS="tiled_ikj_omp"                 # solo esa variante
make results VARIANTS="morton_avx512 tiled_ikj_avx512" MS="4096 8192"
make results ITERS_PER_RUN=0                          # I_full, 1 run
make results ITERS_PER_RUN=0 RUNS=3                   # I_full, 3 runs (override)
```

**Argumentos:**

| Variable | Default | Descripción |
|---|---|---|
| `VARIANTS` | todas (13) | Lista de variantes a medir, separadas por espacios |
| `MS` | `1024 2048 4096 8192 16384 32768` | Tamaños de matriz (2¹⁰ a 2¹⁵) |
| `ITERS_PER_RUN` | `1` | Iteraciones por run. `0` activa `I_full = 2·m/n` |
| `RUNS` | `3` (o `1` si `ITERS_PER_RUN=0`) | Runs medidos para la mediana |

**Variantes válidas:** `naive`, `morton`, `morton_avx512`, `morton_omp`,
`loop_ijk`, `loop_ikj`, `loop_jik`, `loop_jki`, `loop_kij`, `loop_kji`,
`tiled_ikj`, `tiled_ikj_avx512`, `tiled_ikj_omp`.

---

### `make profile_zen5`

Igual que `results` pero consolida sin `--out results/metrics.csv`.
Acepta los mismos argumentos. Útil para correr el sweep sin sobreescribir
`metrics.csv`.

```bash
make profile_zen5
make profile_zen5 VARIANTS="loop_ikj" MS="4096"
```

---

### `make profile_zen5_one`

Perfila una sola celda `(variante, m)`. Útil para debugging puntual.

```bash
make profile_zen5_one                                 # morton_avx512, m=4096
make profile_zen5_one VARIANT=loop_ikj M=2048
make profile_zen5_one VARIANT=tiled_ikj_omp M=8192
```

| Variable | Default | Descripción |
|---|---|---|
| `VARIANT` | `morton_avx512` | Una sola variante (sin plural) |
| `M` | `4096` | Un solo tamaño |

---

### `make profile_zen5_omp`

Perfila `morton_omp` con OpenMP multi-hilo a varios tamaños.

```bash
make profile_zen5_omp
make profile_zen5_omp THREADS_OMP=4 MS_OMP="4096 8192"
make profile_zen5_omp BIND_OMP=close
```

| Variable | Default | Descripción |
|---|---|---|
| `THREADS_OMP` | `8` | Número de threads OMP |
| `BIND_OMP` | `spread` | Política de binding (`spread` / `close`) |
| `MS_OMP` | `1024 4096 8192` | Tamaños a medir |

---

### `make consolidate_zen5`

Re-ejecuta solo el consolidador Python sin repetir el sweep de perf.
Útil tras editar `scripts/consolidate_perf_zen5.py`.

```bash
make consolidate_zen5
```

## Targets auxiliares

### Unit tests

Capa por debajo de `validate_*` (ver [`1.9) tests.md`](<1.9) tests.md>)). Compilan a `bin/tests/`.

| Target | Qué hace |
|---|---|
| `make tests` | Compila y corre los 4 unit-tests en orden, aborta al primer fallo |
| `make test_matrix_utils` | Solo `bin/tests/test_matrix_utils` |
| `make test_morton` | Solo `bin/tests/test_morton` |
| `make test_kernel_avx512_morton` | Solo `bin/tests/test_kernel_avx512_morton` (microkernel 4x32) |
| `make test_kernel_avx512_tiled` | Solo `bin/tests/test_kernel_avx512_tiled` (microkernel 6x32) |

`make validate` depende de `make tests`, así que un fallo en los unit-tests aborta antes de correr los validate.

### Otros auxiliares

| Target | Qué hace |
|---|---|
| `make audit` | Verifica que Morton no emita instrucciones PDEP/PEXT |
| `make hwinfo` | Imprime el fingerprint de hardware (CPU, cachés, RAM, flags) |

## Limpieza

```bash
make clean        # elimina bin/, build/, perf.data, gmon.out
make distclean    # clean + elimina results/*.csv y plots/*
```
