# Makefile — Referencia de uso

## Flujo principal

```
make build          # 1. Compilar todo
make validate_all   # 2. Verificar corrección (puerta antes de medir)
make results        # 3. Sweep perf → results/metrics.csv
```

---

## Targets principales

### `make build` / `make all`

Compila los 8 binarios `bench_*_O3` y los 8 `validate_*` sin ejecutar nada.
No acepta argumentos.

```bash
make build
```

---

### `make validate_all`

Compila (si hace falta) y ejecuta los 8 `validate_*` en secuencia.
Para en el primer fallo. Sin argumentos.

```bash
make validate_all
```

---

### `make results`

Target principal del proyecto. Construye todos los benchmarks, lanza el sweep
de hardware counters con `perf` y consolida la salida en `results/metrics.csv`.

```bash
make results                                        # defaults completos
make results MS="1024 4096"                         # solo esos tamaños
make results VARIANTS="tiled_ikj_omp"               # solo esa variante
make results VARIANTS="morton_avx2 tiled_ikj_avx2" MS="4096 8192"
make results ITERS_PER_RUN=0                        # I_full, 1 run
make results ITERS_PER_RUN=0 RUNS=3                 # I_full, 3 runs (override)
```

**Argumentos:**

| Variable | Default | Descripción |
|---|---|---|
| `VARIANTS` | todas (13) | Lista de variantes a medir, separadas por espacios |
| `MS` | `1024 2048 4096 8192 16384 32768` | Tamaños de matriz (2¹⁰ a 2¹⁵) |
| `ITERS_PER_RUN` | `1` | Iteraciones por run. `0` activa `I_full = 2·m/n` |
| `RUNS` | `3` (o `1` si `ITERS_PER_RUN=0`) | Runs medidos para la mediana |

**Variantes válidas:** `naive`, `morton`, `morton_avx2`, `morton_omp`,
`loop_ijk`, `loop_ikj`, `loop_jik`, `loop_jki`, `loop_kij`, `loop_kji`,
`tiled_ikj`, `tiled_ikj_avx2`, `tiled_ikj_omp`.

---

### `make profile_zen2`

Igual que `results` pero consolida en el CSV por defecto del script Python
(sin `--out results/metrics.csv`). Acepta los mismos argumentos que `results`.
Útil para correr el sweep sin sobreescribir `metrics.csv`.

```bash
make profile_zen2
make profile_zen2 VARIANTS="loop_ikj" MS="4096"
```

---

### `make profile_zen2_one`

Perfila una sola celda `(variante, m)`. Útil para debugging puntual.

```bash
make profile_zen2_one                              # morton_avx2, m=4096
make profile_zen2_one VARIANT=loop_ikj M=2048
make profile_zen2_one VARIANT=tiled_ikj_omp M=8192
```

| Variable | Default | Descripción |
|---|---|---|
| `VARIANT` | `morton_avx2` | Una sola variante (sin plural) |
| `M` | `4096` | Un solo tamaño |

---

### `make profile_zen2_omp`

Perfila `morton_omp` con OpenMP multi-hilo a varios tamaños.

```bash
make profile_zen2_omp
make profile_zen2_omp THREADS_OMP=3 MS_OMP="4096 8192"
make profile_zen2_omp BIND_OMP=close
```

| Variable | Default | Descripción |
|---|---|---|
| `THREADS_OMP` | `6` | Número de threads OMP |
| `BIND_OMP` | `spread` | Política de binding (`spread` / `close`) |
| `MS_OMP` | `1024 4096 8192` | Tamaños a medir |

---

### `make consolidate_zen2`

Re-ejecuta solo el consolidador Python sin repetir el sweep de perf.
Útil tras editar `scripts/consolidate_perf_zen2.py`.

```bash
make consolidate_zen2
```

| Target | Qué hace |
|---|---|
| `make plots` | Lee `results/metrics.csv` y genera 8 figuras en `plots/`: `gflops_vs_m.png`, `speedup_vs_naive.png`, `best_per_family.png`, `efficiency_pct_peak.png`, `perf_breakdown.png`, `cache_hierarchy.png`, `omp_scaling.png`, `roofline.png`. Requiere `matplotlib` en el venv. |

## Targets de compilación individual

Para compilar un solo binario sin tocar el resto:

```bash
make bench_naive_O3
make bench_loops_O3
make bench_morton_O3
make bench_morton_avx2_O3
make bench_morton_omp_O3
make bench_tiled_ikj_O3
make bench_tiled_ikj_avx2_O3
make bench_tiled_ikj_omp_O3

make validate_naive
make validate_loops
make validate_morton
make validate_morton_avx2
make validate_morton_omp
make validate_tiled_ikj
make validate_tiled_ikj_avx2
make validate_tiled_ikj_omp
```

